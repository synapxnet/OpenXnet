# 全局人工审批弹窗

用户要求有人工审批时主动弹窗，并将最终安装器直接更新到 `E:\SynapXnet\openxnet-desktop\OpenXnet-Setup-1.3.0-win-x64.exe`。

## 界面与接入

- 企业身份可用时恢复当前所有工作空间的待批请求；不依赖正在打开的菜单、当前事件或指挥台筛选。使用现有只读 Competition 快照接口，不启动模型、取证或执行。
- 新请求和软件恢复时尚未处理的请求主动打开全局对话框。对话框明确显示业务任务、工作空间、运行来源、申请理由、执行步骤和失败补偿范围；计划、资源版本和参数摘要放在可展开的依据中。
- 有多个请求时排队，正在审阅的计划不被新请求替换。关闭只代表稍后处理，当前会话不反复弹同一请求；屏幕固定的待批入口可随时重新打开。
- 默认“仅批准，执行前暂停”；选择“批准并自动执行”时按钮同步明确表述实际行为。拒绝和批准必须为人点击，前端不填造身份，服务端使用可信登录身份和职责分离检查。
- 登录账户切换、退出企业权限或页面销毁清理弹窗、草稿、定时器与异步代数；迟到读请求不能重开前账户的审批。
- 全局轮询复用现有运行观察：活动任务 3 秒、无活动任务 15 秒；首次登录立即读取。不额外启动生产任务。

## 审批边界

## 轻量审批卡片调整（人工视觉反馈）

用户反馈首版弹窗过大。默认宽度改为 540px，高度上限为窗口 76%，不改变居中、键盘焦点与审批校验。首屏保留任务、申请原因和决定按钮；授权步骤与补偿范围、版本追踪和选填意见分别按需展开。展开后只在内容区滚动，底部决定方式和按钮始终可见；关闭仍为稍后处理。默认仅批准，明确选择自动执行后才改变按钮含义。未展开不自动批准或扩大授权。

## 固定计划校验

多项审批使用左侧便签导航，显示顺序、任务和所属工作空间，并以主色显示当前选中项。界面保留 540px 审批卡片，不将任务堆成大弹窗；小于 800px 的窗口改为顶部横向便签。只有用户明确点击才切换冻结目标，新请求进入列表而不抢占当前项。待批、已决和失效分别显示；提交期间所有便签禁用。意见与执行方式按完整计划指纹保存于当前账户的临时草稿，计划变化不继承旧草稿，退出账户清理。

弹窗冻结原始审批 ID、空间、事件、Trace、计划 ID/摘要和授权步骤；提交前重新读取确认。客户端提交 `expectedPlanDigest`，后端在持久化事务中再次确认审批属于当前运行且计划、范围均未变化。旧计划已经被替代时，保留明确失效提示，原按钮不能审批新的计划。

验证审批展示不等于自动批准；弹窗关闭、刷新、查看详情均为只读行为。现有工具调用审批与内核审批保持各自授权协议，不混用 Competition 审批 ID。

## 验收与交付

覆盖首次恢复、关闭后重开、多个工作空间、新计划替换、重复点击、网络错误后重试、账户切换和明暗/窄窗口。真实审批点击仅在本地隔离示例中模拟回执，未获得独立授权不审批用户生产操作。

构建基于上一协作群修复包，按逐文件白名单纳入本轮文件；检查 TypeScript、生产模板、回归、解包完整性和独立冷启动。备份根目录旧产物后更新原安装器、对应校验和/更新元数据，以及根目录解包程序，避免继续启动旧版。不会自动运行安装器或改已提交的 GitHub 标签。
