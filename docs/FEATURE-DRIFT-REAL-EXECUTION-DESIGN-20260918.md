# 真实特征漂移执行链：实施与验收设计

## 目标与事实边界

负责人已明确要求先补齐真实执行链，再录企业沙盘入口的成功/失败补偿视频与三平台变化视频。当前已安装桌面为 1.3.0 / 20260918-approval-notices，优先兼容其冻结计划及已有审批弹窗。

本次将既有 risk 比赛内存状态分支替换为独立、实际执行的 Staging 运行时。输入明确为可再生的合成风控样本；回填、训练、保存模型、路由推理、采样与回滚必须真正执行。不表述为生产风控收益，不用写数据库展示记录代替实际操作。现有其他场景与历史记录保留来源，不把新执行器结果回写成旧 Run 的证据。

## 分工与接口

- 根执行者：共享设计、AgentTeams Live 网关的受限环境准备、部署备份/切换/回退、整体联调与录屏。
- 实际执行器：`services/feature-drift-runtime`；每 Workspace / Incident 隔离合成源数据、回填集、训练产物、动作台账、路由与独立探针。GET 不创建环境；显式 POST 初始化，重复初始化不重置已有事件。
- 三平台后端：在风险场景的既有白名单工具及审批校验之后调用运行时；未配置或失败时明确失败，禁止回落到原来的固定成功值。驻场服务提供受网页登录保护的只读证据代理。
- 三平台前端：从原生工作台入口展示本次跨域任务，读取相同运行时账本；保留 Workspace、Incident、Trace、Approval、实际产物和测量时间关联。原生旧 v18 记录不能伪装成新执行器已更新的部署。

运行时的详细 HTTP 数据契约在其目录设计文档维护，平台后端与前端设计需引用同一版本。读取统一位于 `/api/resident/v1/feature-drift/runs` 与 `/runs/{incidentId}`，由驻场服务验证登录身份和工作空间授权，不向浏览器暴露运行时密钥。

## 执行与治理

1. 用户启动新事件后，服务器为获授权的 Workspace / Incident 显式准备隔离测试环境，记录数据种子、范围、摘要与真实源数据。此步骤不能更改线上生产资源，也不能重置现有事件。
2. 取证读取该环境的实际输入契约、模型与探针，并清楚标注合成 Staging 来源。
3. 原有具体计划及补偿范围经人工批准后，各平台校验审批、参数摘要、资源版本和幂等键，再调用真实动作。模型不能自行创建执行权限。
4. 合成数据确实覆盖请求的 36 个月；回填必须读取源行、执行转换并写出版本化数据集。返回真实行数、质量计数、来源摘要和时间范围。
5. 按当前获批参数实际执行 12 次有界 CPU 训练试验，覆盖 LightGBM 与 WideAndDeep。不能将其他算法冒充被批准算法。验证集用于选择，独立持出集不参与训练或选择。
6. 灰度路由实际分配请求，返回请求计数、样本数和实际持续时间。比赛采用压缩观察窗，不能把请求的 30 分钟写成已完成的真实观测时长。
7. Verifier 读取独立推理结果和状态，不能把执行回执或 promoted 布尔值当作恢复指标。时间不足、样本不足、契约或质量失败都必须阻止关闭。
8. 失败分支在独立事件创建时固定受控故障，执行后真实读回失败，再执行获批的旧产物/路由回滚。补偿成功与业务未恢复分别记录。故障不影响成功事件或其他工作空间。

为兼容已安装桌面，失败注入由部署管理员在新事件启动前预置精确 Workspace + Incident 的私有故障计划文件；模型不能传入故障模式。网关在首次显式初始化时读取此计划，之后不可重置。运行时证据与视频显示该受控故障的来源。该设置只准备隔离演练初始条件，不替代画面中的取证、人工批准、执行或独立验证。

## 部署

运行时只在容器内网监听，采用独立持久化目录；初始化、各平台动作及只读观察使用分角色凭据与工作空间白名单。凭据通过私有文件或现有部署管理注入，禁止进入源代码、公开回执或录屏。

部署前只读盘点当前服务、路由、镜像/产物摘要和挂载。备份本次触及的前端静态文件、代理配置、后端原件和容器配置；保留旧容器/制品以便回退。候选服务先独立启动和健康检查，再切换限定路由。禁止整库覆盖或迁移不相关数据。

## 验收与录制顺序

首先测试算法和实际制品、错误参数拒绝、无审批拒绝、资源版本冲突、幂等重试、跨事件/空间隔离、重启续接、独立探针失败和回滚恢复。随后测试真实部署的 API、同事件三平台页面和完整 AgentTeams 链路，记录所用版本及证据。

正式录制必须使用新的事件，先录本轮基线，再从企业沙盘进入成功任务并点击人工批准；失败使用独立事件并保留故障来源。第二段录同一次成功任务在三平台的真实前后变化。原片、时间线、来源映射与脱敏证据单独保留，人工批准和终态不加速；等待压缩需标注。完成视频解码、关键帧与内容核查后，才投递到决赛提交目录。
