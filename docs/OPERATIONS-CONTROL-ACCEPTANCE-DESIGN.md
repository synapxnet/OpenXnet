# 正式运行指挥台与 GOAI 触发入口

运行指挥台是长期产品能力。它以工作空间为范围展示运行记录、人工审批、平台身份与证据采集，默认汇总全部空间，可筛选空间、状态和关键词。所有实际记录均可访问，不截断为固定八条。

GOAI 页面只管理演练草稿、场景/路径选择及新事件创建。主场景固定推荐“跨域特征漂移恢复”；保留容量和量化场景作为可复用能力。创建成功后进入正式运行详情。生产版本隐藏演练入口，但运行、审批、审计和项目群入口继续工作。

## 界面与对接

- 运行指挥台：全部/单工作空间筛选、当前运行列表、跨空间待审批队列、独立平台状态。
- 运行详情：复用现有取证、团队、审批计划、执行、验证、补偿、Skill、审计组件，仅保留一份模板；在指挥台内打开，并提供返回列表。
- 审批队列：仅收录 incidentId、workspaceId、activeTraceId、activeApprovalId 全部匹配且状态为 PENDING 的原审批。进入详情时再次核对；仅导航不批准，批准/拒绝仍走原 IPC 与后端校验。
- 配置引导按“沙盘 → 企业空间 → 员工 → 团队 → 分配工作空间 → 事件 → AgentTeams”排列。当前数据模型的沙盘是企业空间的共享视图，没有独立沙盘实体；界面明确显示此事实，不虚构已创建实体。空间、员工与模板均按当前工作空间核对；AgentTeams 完成状态必须来自当前 Trace 的真实绑定。
- HUD/灵动岛承担提醒和定位；正式详情承担完整审批范围与审计。此次不把高风险审批压缩到提醒浮层。

## 验收顺序

1. 登录后进入沙盘，再检查企业空间、员工、协作团队和空间分配；缺项有明确原因及直接入口。
2. GOAI 入口选择真实工作空间，创建特征漂移事件；切到正式详情后检查团队匹配和选中态。
3. 三个工作空间并存时，全部运行和待审批可汇总，筛选互不串线。错误空间/Trace/旧审批不得进入队列。
4. 审批前查看完整写入/补偿范围，人工决定后观察执行、独立验证、失败与恢复；不得因导航触发执行。
5. 回到列表仍保留筛选和选中记录；从项目群审计进入同一正式详情。
6. 桌面真实页面检查浅/深色、侧栏开合、窄屏、长名称和空/错误状态，再执行相关回归并打包。

## Fixture 证据摘要一致性修正（2026-09-16）

实机验收发现：特征漂移场景返回服务健康、错误率 0.001、P95 95ms、3/3 副本且重启 0 次，但摘要仍称“服务异常”“未就绪副本和重启”。根因是摘要只按整个事件是否处置完成分支，没有读取该工具返回的实际领域状态。

修正范围：仅调整 Fixture 的只读证据摘要，复用生成数据时的场景判定，并读取实际健康度、副本/重启、告警指标、质量状态、工作流警告与探针通过结果。主场景明确区分“基础设施健康”和“业务预测退化”；不修改证据数值、审批规则或执行路径。容量场景继续呈现服务退化和 GPU/队列拥塞，不因尚未处置就虚构副本重启。

回归需要覆盖：特征漂移处置前基础设施健康但预测错误率告警仍触发；容量场景仍有高延迟与拥塞；质量通过、工作流成功和探针通过不得显示失败摘要；处置后及验证失败路径继续与真实响应一致。

## Builtin 独立验证完成门禁修正（2026-09-16）

实机发现 Builtin 运行已通过真实独立验证且进入 RESOLVED，前端却只寻找 AgentTeams 的 Verifier 对话裁决，导致完成门禁停在 6/7。修正使用真实 `openxnet.remediation.verify` 审计回执的结构化 `verification` 结论，核对工作空间、事件、活动 Trace、动作、独立执行身份以及完整验证证据；Builtin 显示“内置独立验证”，AgentTeams 额外要求实际 Verifier CLOSE 决策。历史无结论字段的记录保持“缺少可核验回执”，不能从 RESOLVED 反推成功。

回归覆盖同范围成功与失败、外空间/旧 Trace、错误执行身份、缺失验证证据及 AgentTeams 未给出 CLOSE 的拒绝关闭。

## 驻场上下文数量与身份排版修正（2026-09-16）

驻场卡片使用当前工作空间、事件、活动 Trace、Agent 与平台匹配的 `residentContexts.evidenceRefs` 唯一非空引用数，明确标为“上下文证据”，不再把所有历史 `EVIDENCE_COLLECTED` 事件次数当作证据数量。身份与本次运行证据的说明各自独立成行，避免窄卡片中连续挤断字。历史数据只读，外空间与旧 Trace 不计入。

## HUD 主题与近期快照接线修正（2026-09-16）

实机发现主窗口深色而 HUD 浅色，且任务完成后打开 HUD 没有近期记录。两者均存在伴随窗口专用 preload 缺少接线：皮肤只读了旧 localStorage，未读主窗口已迁移的 Main 皮肤库；完成事件桥已有静默快照能力，但专用 preload 未暴露读取、订阅与按结果身份导航接口。

伴随窗口获得限定的皮肤只读与变更订阅能力，皮肤写入仍仅主窗口可用，保存成功后通知现存伴随窗口重新读取经过验证的库。启动与 DOM 就绪时应用同一保存皮肤，网页模式保留旧存储回退，不写入、不迁移偏好。完成桥只暴露已有近期快照、通知订阅与按结果 ID 导航，不开放发布、审批或执行；恢复快照不弹通知、不执行动作。近期历史目前仅保留在 Main 进程内，程序重启后的旧 Run 历史恢复不在此次范围。

## 取证规划与观测事实分离（2026-09-16）

实际 AgentTeams 取证规划阶段尚未收到证据，模型原始摘要却可能提前描述“调用已完成”或服务健康指标。运行指挥台的规划决策卡与上下文交接主文案改由真实 `requestedToolNames` 生成：显示已选择的唯一非空工具数量；同工作空间、事件与活动 Trace 存在对应工具的实际结束调用时，提示查看实际采集结果，否则提示等待采集证据。该文案不从原始模型摘要推导调用完成、健康指标或业务结论。

原摘要完整保留在默认折叠的“模型原始规划说明（不作为观测证据）”审计区域，其他决策阶段继续展示原始结论。仅调整只读展示，不改决策、证据、正在运行的 Trace、审批或执行流程；回归覆盖空证据规划、真实采集、旧 Trace/外空间不得借用及其他阶段摘要保持原样。

## 灵动岛折叠态点击修正（2026-09-16）

实机折叠条可见但点击命中背后窗口。原实现默认设置整窗鼠标穿透，等待悬停事件经 Renderer→Main 异步往返后再接收点击；首次点击或折叠/尺寸同步竞争可能继续穿透。灵动岛窗口已紧贴可见内容并有尺寸上限，因此保持折叠与展开态均可点击，移除依赖悬停解除整窗穿透的前置条件。Main 将旧 Renderer 的 `interactive:false` 规范为可交互状态，重开时重新应用状态；不扩大窗口、不改变任务权限和导航。

折叠正文原本只用透明度和最大高度隐藏，仍保留内边距、可访问性子项及过渡中的裁切碎片。补充仅针对折叠态直属正文的 `display:none`，展开态仍使用现有内容和滚动布局。回归执行实际 Main 状态函数与真实页面同步函数，覆盖首次打开、重开、折叠、展开及旧悬停状态不再锁死。

## 总览右栏横向裁切修正（2026-09-16）

实机 1352×722 左栏展开时，运行指挥台右侧待审批徽标和平台入口被右边界裁切。样式核对发现总览 grid 同时使用 `width:100%` 与左右 20px 内边距，却没有限定盒模型，内容盒宽度会额外增加 40px；右栏已有 `min-width:0`，无法抵消父容器的总宽溢出。另外后置企业空间样式覆盖了容器名称，`ops-control` 未恢复 `competition-host`，内容宽度断点没有生效。

仅在运行指挥台总览子树采用 `border-box`；右栏内部单列网格允许收缩，标题文字允许换行而数量徽标保持完整，平台按钮受其列宽约束。为正式运行页恢复既有容器名称，让 850px 与 520px 的原有内容断点继续工作。不缩放界面、不隐藏右栏、不改变工作空间或运行状态。回归确认有内边距的满宽容器采用同一盒模型、右栏子项可收缩、正式页具备有效内容断点，再交由实机复查边界。

同一截图中的三平台入口还继承了原生按钮灰底。此次仅将这三个入口显式接入已有皮肤的面板背景、边框、文字与强调色，继承软件字体，保留悬停和键盘焦点反馈，不改导航行为。

## 主题保存同步 IPC 崩溃修正（2026-09-16）

最终实机切换浅色时出现 `Cannot read properties of undefined (reading 'ok')`。新增伴随主题广播在写入 `event.returnValue` 后读取其 `.ok`；Electron 的同步回复属性采用 setter 发送结果，不能假定赋值后还能读回。既有测试将事件表示成普通对象，未覆盖该原生行为。

修正把经过验证的读写结果保留在局部变量，以该变量判断是否广播，再通过 `event.returnValue` 发送同步回复；不再读取回复属性。测试事件统一使用 setter-only 回复属性，全部既有读写、未授权、损坏输入、写入失败和清理场景在该语义下运行，并补充连续深浅主题保存及伴随广播异常不影响成功回复。主窗写入权限与伴随只读权限维持分离，不修改皮肤库之外的任何业务记录。
