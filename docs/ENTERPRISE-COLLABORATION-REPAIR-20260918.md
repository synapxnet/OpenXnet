# 企业协作群修复与验收约定

本说明先于本轮主线集成修改。范围为桌面企业空间的工作空间/项目协作群。

## 已确认缺口

1. 群聊的 AgentTeams 临时转发与持久决策不是同一条可靠路径。转发依赖当前角色卡和成员归属，失败只写日志，历史任务不会在重新打开群时补齐。治理操作卡独立记录，因此用户可能只看见 OpenXnet Governance。
2. 输入框没有 @ 候选弹层。现有成员按钮仅维护收件人数组和文本；删除可见 @ 可能留下隐式接收人。
3. `VERIFICATION_FAILED` 被映射为消息 `status=failed`，前端将其显示为“发送失败”，混淆业务结果与消息投递。

## 实施边界与接口

- AgentTeams 消息从已保存的决策、可信路由与绑定成员快照派生；保留真实角色身份、任务阶段、证据和关联来源。没有对应记录时不生成冒充模型的发言。
- 新任务增量写入，旧任务在读取协作群时按范围补齐；稳定来源标识支持幂等，跨工作空间/项目隔离。投影故障应在群聊可见，不影响审批、执行或独立验证结论。
- 治理、人工审批及补偿通知仍使用系统身份。已落盘的治理失败卡属于已投递，业务失败继续由操作卡展示；对旧记录只做展示兼容，不重写历史审计。
- `@` 候选仅使用当前可用成员。选择写入可见标记与稳定员工 ID，删除/修改后重新核对，切换范围关闭候选且保存各自草稿。支持鼠标、上下键、Enter/Tab/Escape、中文输入法与无匹配状态。
- 普通“发送”发布群留言；“发起任务”启动受控 AgentTeams 流程。选中或手输 @ 不构成审批，不触发生产操作，不承诺尚未实现的自动问答。
- 不在协作群暴露系统提示词、隐藏推理或凭据。仅展示可公开的阶段结果、任务交接和证据引用。

## 验收顺序

1. 在隔离数据中建立真实格式的 Workspace、项目、角色与团队绑定。
2. 验证 Leader → Evidence Worker → Leader → Independent Verifier 的实际记录可进入同一个群，刷新/重启不重复，旧记录补齐不改变原治理消息。
3. 验证其它工作空间/项目的数据不出现，成员变更不将历史发言换成当前选中员工，Builtin 无记录时不伪造 AgentTeams 对话。
4. 输入 @ 并筛选、键盘/鼠标选择、删除、群切换、中文组合输入，检查收件人和草稿一致；选择 Enter 不发送。
5. 验证“独立验证未通过”的失败卡可见且不再显示“发送失败”，真正投递失败继续提示。
6. 类型检查、针对性行为/持久化测试、生产模板编译，再做明暗主题及窄窗口的浏览器交互验收。

## 发布口径

本轮修复不覆盖已公开的 v1.3.0 发布标签与决赛录屏。源码与本地验收记录单独保存；任何后续安装包必须包含新桌面核心与重新生成的页面模板，不能只替换浏览器预览。

打包验收发现普通启动会注册操作系统的 `sap://` 协议，仅隔离用户目录无法隔离该注册表副作用。冷启动验收必须同时指定独立用户目录、启动报告及报告后退出；该专用组合跳过协议注册、开机自启写入、全局快捷键注册与托盘创建。正常用户启动保持原行为。冷启动前后还应只读对比协议及自启注册表摘要，确认没有影响当前安装。
